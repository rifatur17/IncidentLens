# Next ESLint glob compatibility boundary

The workspace override replaces **only micromatch under fast-glob 3.3.1**, used
by Next ESLint 16.3.8. It does not disable a rule, rename a vulnerable copy, or
change Next's root-directory resolver. The vulnerable `braces` package and its
AST walkers are absent from the resolved dependency graph.

fast-glob calls three micromatch methods: `scan`, `makeRe`, and
`braces(pattern, {expand: true, nodupes: true})`. The first two delegate to the
same Picomatch 2.3.2 implementation previously used by micromatch. Expansion
uses patched brace-expansion 5.0.12, preserving nested, padded, stepped and
descending ranges. A linear literal-protection pass preserves quoted strings
and character classes without a recursive parser. Empty expansions are filtered
by fast-glob itself, just as before. Resource limits in the patched expander and
the original 64 KiB input ceiling remain in force. Pathological brace nesting
beyond 128 levels is rejected explicitly before expansion or matching, including
when reached through Next's real glob dependency.

Keeping fast-glob preserves filesystem traversal, absolute paths, Windows path
normalization, symlink handling, hidden-directory behavior and path formatting.
The adapter deliberately fails closed on unreviewed brace options. Review this
boundary whenever Next, fast-glob, or their call sites change; it is not a general
micromatch replacement for arbitrary consumers. Remove the override once an
upstream dependency update safely eliminates the affected chain.

Run `pnpm --filter @incidentlens/eslint-glob-compat test`. The reference fixture
outputs were captured from the original fast-glob 3.3.1 before replacement, not
generated by the adapter. Regression tests also invoke Next's actual root helper
and pages-link lint rule, and exercise malicious brace nesting. CI runs these
tests before the existing frontend checks. No original vulnerable dependency is
installed as a test dependency or excluded from audits.
